How to read the map

The map lists open subsurface datasets: wells, seismic, horizons, production. Each one is described by a record that repeats what its publisher says. This page explains the level next to each dataset, how to take a layer into your own tools, and how to add a dataset.

The levels

Every dataset carries a level. A tool sets it by checking the dataset; nobody types it by hand. The levels are a ladder: a dataset reaches a level only after it has passed every level below.

LevelWhat it meansWho checks it
L0 listedA record exists with the publisher, the place to get the data and the licence, as the publisher states them.a contributor, by pull request
L1 reachableThe publisher's page for the dataset answers.the verifier, over the network
L2 checksummedThe files have been fetched and hashed, and the licence text has been saved.the verifier
L3 outlinedThe wellbores and survey outlines on the map were read from the data itself.the outline extractor
L4 convertedThe data has been read into a standard form, with a record of what was kept and what was lost.the Ophiolite readers

stale next to a level means the last check is more than 30 days old. The level was true then; it may not be now.

The Why this level row of a dataset, and the Why column of the status page, give the verifier's own sentence and the day it checked. Below L2 it names the check that stopped the climb: never verified (no check has run yet); no file address is published to us (the record names no file listing; a publisher can publish one, a CKAN package, a file index or a direct download); the listing names no files (the listing answers but lists no downloadable file; a publisher can add the file addresses to it); robots.txt disallows the listing (a publisher can allow the agent osd-verifier in robots.txt); answers a browser, not the verifier, or blocked from this runner with a 403 or a challenge page (the origin refuses automated requests, which is not the same as the data being gone; a publisher can answer robots the same as browsers); HTTP 502, 404 or no answer at all (the origin is down or gone; it rises again when it answers). At L2 and above the sentence is the evidence: how many files were hashed, the outline derived or the conversion. A blocked dataset shows the date the refusal began instead of a level, because it awards none.

A dashed outline is a placeholder drawn by hand to show roughly where the data lies. It is not taken from the data, and it keeps the dataset at L1 or below. A blue dashed rectangle is the area the record states, not the data's real footprint. Green circles are wellbores; where they are dense they are grouped into one circle with a count until you zoom in.

The years under the list's publisher name, and the When row of a dataset, are the period the publisher states for the dataset as a whole, with where they state it. They are not the dates of single wells or surveys; those are in the dataset's STAC Items. The From and To years on the map show the datasets whose period overlaps them; a dataset whose publisher states no period stays listed unless you tick "only dated datasets".

Taking a layer into your own tools

Every outline on the map is in one GeoJSON file, in longitude and latitude (EPSG:4326). Each feature has a record_id that names the dataset it belongs to. The detail panel on the map shows these three cards for the dataset you selected; here they are for Volve.

Open in QGIS Layer → Add Layer → Add Vector Layer. Source type: Protocol: HTTP(S). URI: the address below. Then filter the layer on record_id. 
https://opensubsurfacedata.org/data/outlines.geojson
Read in Python Standard library only. This keeps the features of one dataset. 
import json, urllib.request
fc = json.load(urllib.request.urlopen("https://opensubsurfacedata.org/data/outlines.geojson"))
mine = [f for f in fc["features"] if f["properties"]["record_id"] == "equinor/volve"]
print(len(mine), "features")
Get the data The data itself stays with its publisher. The record names where to get it and under which licence; this prints both. 
import json, urllib.request
recs = json.load(urllib.request.urlopen("https://opensubsurfacedata.org/data/records.json"))["records"]
volve = next(r for r in recs if r["id"] == "equinor/volve")
print(volve["origin"]["url"], "|", volve["licence"]["name"])

Fetching the files by a manifest, and reading them straight into Ophiolite, are planned but not built yet.

A dataset that comes with a starter project shows a fourth card, Starter project: one button per application the pack was built for (OpendTect, ResInsight, Python) with the version it was built against, the pack's licence, a link to what we decided (coordinate system, depth reference, units, null values, log names, each with its source), and the three steps to open it: download the pack manifest, run osd get on it, run the import for your application. Tick "with a starter project" under Show to see only those datasets.

The licence rule

The publisher's page is the authority. A record repeats what the publisher says about the licence, including unknown when the publisher does not say. Nothing on this site is legal advice. Before you use or share a dataset, read the licence on the publisher's own page.

Adding a dataset

  1. Copy records/_template.yaml to records/<publisher>/<dataset>.yaml in the repository.
  2. Fill in only what the publisher states. unknown is a fine answer for a licence field.
  3. Open a pull request. The check validates the record and tries the publisher's page, and a reviewer compares the licence fields with that page.

An outline can be added the same way, under outlines/. See CONTRIBUTING.md.
